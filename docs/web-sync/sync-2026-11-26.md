## Deviations recorded in this sync

Sandbox and API:

- Charges are on by default, as on the web. Test harnesses that assert balances to the paisa run with charges off, as the web's suites do (`sandbox_support`, `sandbox_concurrency`, the golden replay).
- `/api/v1/charges` calls are not written to the order log, like the desktop's `/api/v1/margin`; the web logs them without the key (lead ruling, accepted).
- `/api/v1/charges` and the calculator refuse a trade value above 10^15 with a sentence; the web prices any size (`7e4ad22d`).
- The cost report sums in exact decimals; the debit is written before the trade row in the same transaction; `/sandbox/update` accepts the plan's keys under the same checks. No visible effect.
- `tests/fixtures/web/added_after_recording.json` lists the two funds fields the web added after the golden fixtures were recorded; no fixture was edited.
- The calculator's profit green is `text-green-700 dark:text-green-500` (a11y, noted for the web in `a11y-2026-11-25.md`); the desktop-only Sandbox model note names the crypto venue fee.
- The sandbox feed queue has an overall cap (1,024 waiting subscribes, 2,048 calls with releases) with a turned-away symbol asked for again; a subscribe joining one already waiting for its symbol is dropped. The web cancels per symbol only.
- The sandbox's and the strategies' feed references belong to the broker session that took them and are taken again in a new one (`47eefdab`, `75b99a1a`).

WebSocket feed:

- The desktop keeps its `AUTHENTICATION_ERROR` frame and close 4401, and also closes after a new API key, a password change and account setup; the web closes with 1012 on a broker token change only (#2277).
- Pocketful Depth takes its price from the detailed channel where the web uses the compact one; only what is sent to Pocketful differs (declared `broker-facing-flush`). Pocketful keeps `ltt` and the Quote book totals the web now drops (`lost-data-kept`).
- AliceBlue sends `ltt` and the Depth `timestamp` in milliseconds where the web sends seconds, clears a level sent as 0/0, and starts afresh after a reconnect.
- Wisdom sends one request per client message, 0.5 s apart, where the web groups a 0.5 s burst; XTS instrument ids stay numbers (before this sync too).
- Flattrade's order subscribe goes after the login acknowledgement and the catch-up read after the order subscription is written; a push is kept over any later read's row (web defect not copied); catch-up updates carry Flattrade's rejection reason; a refused token is not retried.
- Tradejini: the access token is the session's; a non-finite number skips its event; a short packet costs only its own events; an update with only the trading symbol takes the order book's OpenAlgo symbol (web defect not copied).
- Groww: the detail read's segment comes from the exchange and waits at most 5 s (the web 10 s); the market feed keeps header version 0.0.8.
- 5paisa XTS: a refused stored session holds the feed until the next sign-in; the user id falls back to the one given at sign-in; a first subscribe keeps the desktop's search by halves.

Brokers:

- XTS: a missing order id stays empty, not the web's "0"; position errors read in the desktop's words; a JSON id above `u64::MAX` loses digits in serde_json (residual); modify sends an id past `i64` as text.
- 5paisa XTS Cancel All still cancels "Trigger Pending" orders, which web #2504 dropped from its list (`c3af1ca7`).
- Pocketful: the session keeps the bare token with the account beside it; the resume check after a restart asks the broker with the stored account, for every broker (reviewed safe for every family); BR-03 and the three-outcome rule kept for books and orders; a lost modify or cancel answers 400, the web 502; an unknown status reads "unknown".
- Pocketful funds and margin: margin refusals answer 400, an expired session too; a leg's underlying comes from its symbol, not `name`; unreadable funds are an error, never zero; the position book gets what is left of 10 s inside the resume check.
- Pocketful GTT: a 5xx or an unclear create is uncertain; a write that never left is refused; refusals answer 400 where the web passes Pocketful's status; GTT writes use the order lane's pacer; the instrument type is read from the symbol only.
- Pocketful master: each of the five files must yield instruments; a repeated (exchange, token) keeps its first row; a blank exchange falls back to the file's; the archive is read in memory; the stored master is replaced through the staged swap.
- Pocketful data: a chain leg without OI is reported missing; one deadline per history and per quote batch; a history needing more than 530 requests is refused; daily bars built per chunk; NFO expiries read as DDMMMYY in the 2000s; a data request waits at most 10 s for its turn.
